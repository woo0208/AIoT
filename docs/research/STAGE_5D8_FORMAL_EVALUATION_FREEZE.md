## 1. 평가 과제와 자료 분리

주 평가 과제는 P0~P5 **6-class**, 참가자 단위 **개발 2명 / 독립 검증 4명**이다. 클래스 순서는 기존 `h6_offline.py`의 P0 upright, P1 forward_head, P2 lean_back, P3 lean_left, P4 lean_right, P5 lean_forward를 유지한다. `body_forward`는 P5 lean_forward에 명시적으로 대응한다. 기존 primary5 및 5-B는 별도 과제/산출물로 보존한다.

같은 사람의 세션·반복·프레임은 집단을 넘나들지 않는다. 실제 독립성은 ID 문자열만으로 증명하지 않으며 기존 파일럿 참가자 중복 여부와 인물 독립성 확인은 별도다. 검증 4명은 개발·후보 선택·튜닝에 사용하지 않는다.

## 2. 직접 비교의 공통 표본

직접 비교는 동일 참가자·목표 구간·동일 10초 분석 창과 **비교 대상의 공통 적격 구간 표본**을 사용한다. 모델 선정의 다섯 후보 역시 개발 2명의 같은 공통 적격 표본에서 비교한다. 비교에 참여하는 특징군/후보 집합과 교집합 key·제외 사유를 명시하고, 결과를 보고 비교 집합을 유리하게 바꾸지 않는다.

특징군 전체의 **동일 원시 프레임 교집합은 강제하지 않는다**. 각 특징군의 support·입력 수·유효 수·coverage를 별도로 기록한다. 이는 5-D-3의 F0/F_cal **내부** 공동 support를 해제하지 않는다. 특징군 자체 가용 표본 결과와 공통 비교 결과의 분모를 혼용하지 않는다. F0/F_cal 보정 실패는 H5/H9 자체 적격성을 바꾸지 않으며, F0/F_cal 포함 공통 비교에서만 해당 교집합을 제한한다.

## 3. 시간과 누락

5-D-3의 분석 범위 `[자세 유지 종료−10초, 종료)`와 전환 제외를 유지한다. 검증된 유지 구간이 10초보다 짧거나 시간축/종료 근거가 불충분하면 **unprocessed**로 처리한다. 보충 프레임·창 이동·host 시각 대체로 복구하지 않는다.

프레임 누락률은 신뢰 가능한 **동일 스트림의 원래 프레임 번호**로만 산출한다. RGB/depth 등 스트림, 원천·연속성 근거를 명시하며 loader의 행 번호·재생 인덱스를 센서 프레임 번호로 대신하지 않는다. 근거가 없으면 누락률 미산출/사유 기록이며 0%로 간주하지 않는다. 누락률은 5-D-3 coverage(`공동 유효 수 / 분석 창 실제 입력 수`), 실제 FPS 및 nominal FPS와 구분한다. 신뢰성 확인·counter reset/중복/경계 및 누락률 분모의 세부 산출 명세는 이번 승인에서 새로 정하지 않는다.

## 4. 추가 재촬영

**계획된 촬영 이외의 추가 재촬영은 0회**다. 기술 실패·라벨 불확실·보정 실패는 원본과 사유를 보존한다. 예측 오류를 이유로 재촬영하지 않고 후속 P0로 보정 기준을 교체하지 않는다. 실패/제외 기록을 성공 기록으로 덮어쓰지 않는다.

이는 연구 분석상의 0회 규칙이며, 계획된 촬영의 횟수/세션 부담이나 IRB가 허용하는 재촬영 범위를 확인 완료했다는 뜻이 아니다. 변경하려면 후속 결정과 **IRB 범위 재확인**이 필요하다. 기존 selection/recapture lineage 기능이 있다는 사실은 추가 촬영 허가가 아니다.

## 5. 라벨 포함과 별도 상태

라벨은 모델 예측과 독립적으로 수행을 확인한다. **confirmed이면서 기술적으로 적격인 구간만 포함**한다. ambiguous / mismatch / not_reviewable은 각각 별도 상태·사유로 보존하며 예측으로 confirmed로 바꾸거나 정답을 다시 붙이지 않는다. confirmed도 5-D-3 기술 적격·참조 제외·집단 분리 규칙을 면제하지 않는다.

라벨 확인 담당자·판정 근거·접근/봉인 절차 등 실제 운영은 IRB·동의 범위와 함께 확인해야 하며 이번 문서가 수행 완료를 뜻하지 않는다.

## 6. 불완전 클래스와 참가자 보존

**고정 6개 클래스와 각 참가자의 실제 support**를 기록한다. 참가자별 클래스가 누락되면 **INCOMPLETE**로 표시한다. 사후 클래스 삭제·참가자 삭제로 완전 평가처럼 만들지 않는다. 기술적/라벨 제외가 있어도 해당 참가자의 존재, 계획·시도·포함/제외 수와 사유를 보고서에서 지우지 않는다. 적격하지 않은 값을 모델에 강제로 넣는다는 뜻은 아니다.

zero-support에서 지표의 수치 처리와 INCOMPLETE 표시는 다른 축이다. 수치상 0이 산출되더라도 완전 자료라는 뜻이 아니다. 실제/예측 support를 함께 남기고, 원래 6-class 명세를 5-class 등으로 바꾸지 않는다.

**남은 수치 명세:** 기존 지표 문서의 예측 support=0일 때 Precision=0, 실제 support가 있으나 예측이 없을 때 F1=0 정의는 유지한다. 다만 실제 support=0인 클래스의 Recall/F1 수치(0/undefined 등), 고정 6-class Macro-F1의 그 항목 처리 및 평가 표본이 전혀 없는 경우의 집계는 이번 지시에서 구체적인 수치 규칙이 주어지지 않았다. 이를 임의로 선택하지 않는다. 기존 `rf.macro_f1`의 support=0 클래스 건너뛰기를 정식 고정 6-class 계산으로 자동 승인하지 않는다. 이 세부 명세가 필요한 실행/선정은 추가 결정 전 차단하며 INCOMPLETE 표시만으로 대체하지 않는다.

## 7. 정식 seed와 기존 모델 정의

정식 **RF seed는 (0, 1, 2)**다. 기존 파일럿/보존 실행기의 0~4 결과와 코드는 변경하지 않는다. seed는 참가자나 독립 반복 수를 늘리지 않는다.

LR B0의 기존 결정적 학습 설정을 유지한다. 참조는 `analysis/lr_feature_comparison_20261029_1a6c42/baseline.py`의 기존 Logistic-Regression 생성기와 `analysis/lr_fixed_comparison_20261029_b0r1w1/PLAN.json`의 B0다: C=1, L2(`l1_ratio=0`), lbfgs, tol=1e-4, max_iter=10000, fit_intercept=True, class_weight=None 및 B0의 추가 P0/P1 상대 가중 1.0. R1/W1을 채택하거나 새 LR seed 탐색을 승인하지 않는다. 결정적 LR 결과를 RF 3개 seed처럼 독립 반복으로 세지 않는다.

기존 RF M0/M1/M2 정의와 설정, FEAT-010의 학습 fold 내 MDI·rank-weight 규칙 및 기존 H9 M2 λ=0.5는 유지한다. 새 λ 탐색·가중치·모델/전처리 튜닝을 승인하지 않는다. scaler 등 학습되는 전처리는 해당 개발 학습 fold에만 fit하고 독립 검증 자료에 재fit하지 않는다.

## 8. 지표의 역할

**주 지표는 독립 검증 4명의 pooled 6-class Macro-F1**이다. 참가자별 F1 평균과 혼용하지 않는다. 기존 평가 계획의 seed별 예측에서 해당 scope의 혼동행렬/지표를 계산한 뒤 seed 결과를 요약하는 구조를 유지하며 정식 RF에는 위 세 seed를 적용한다. seed 합산 표본을 독립 참가자로 해석하지 않는다.

Accuracy, 클래스별 Precision/Recall/F1, P0/P1/P5 방향 오류, 참가자별·세션별 지표는 보조다. 혼동행렬과 실제 support·제외 사유를 함께 보존한다. zero-support 수치 정책과 INCOMPLETE 표시는 §6처럼 구분한다. **정식 유의성 검정은 실시하지 않는다.** 기존 초안의 60/120은 보정 참조 포함 수집 목표이므로 실제 분석 분모로 고정하지 않는다.

## 9. 개발 단계 모델 선정

선정 자료는 **개발 2명 LOSO의 공통 적격 표본**이다. 같은 사람의 두 세션을 한 집단으로 묶어 보류한다. 기존 지표 체계의 seed별 두 test fold OOF를 합쳐 scope 지표를 산출한 후 RF seed를 요약하는 구분을 유지하며, 독립 4명의 결과로 순위를 고르지 않는다. 불완전 support의 수치 정책이 필요한 경우 §6의 추가 결정 전 순위를 확정하지 않는다.

우선순위는 다음 순서의 사전 고정 비교다. Recall 묶음은 P0, 그다음 P1, 그다음 P5 순으로 적용한다.

1. Macro-F1 높은 후보
2. 동점이면 P0 Recall → P1 Recall → P5 Recall 높은 후보
3. 계속 동점이면 Accuracy 높은 후보
4. 계속 동점이면 특징 수가 적은 후보
5. 계속 동점이면 아래 고정 후보 순서의 앞선 후보

| 고정 순서 | 모델 | 특징 |
|---|---|---|
| 1 | RF M0 | H9 |
| 2 | RF M1 | H9 |
| 3 | RF M2 | H9 |
| 4 | RF M0 | H9−F9 |
| 5 | LR B0 | H9−F9 |

F0/F_cal/H5는 **비교 기준선**이며 이 최종 후보 목록에 자동 편입하지 않는다. H9−F9는 기존 8열 구성이고 LR B0를 H9 9열이나 다른 특징군으로 바꾸지 않는다. 새로운 ablation·후보 탐색을 승인하지 않는다. 동점 수치의 반올림/허용오차에 관한 새 규칙은 주어지지 않았으므로 임의의 epsilon을 추가하지 않는다.

## 10. 독립 검증 전 최종 동결

최종 모델·특징·전처리·seed·코드/모델 hash를 **독립 검증 4명 평가 전에 동결**한다. 선정과 실제 artifact hash 확정은 개발 단계에서 별도 기록하며 이 문서가 모델 선정/학습 완료나 hash 발급을 뜻하지 않는다. 검증 결과로 모델·특징·전처리·seed를 재선정하지 않는다. 기존 EXP-001의 method freeze 전 검증 자료로 튜닝하지 않는 원칙도 유지한다.

1. **실제 정답 support=0:** 해당 클래스의 Recall은 **N/A**로 기록한다. 해당 독립 평가는 **INCOMPLETE**이며 **공식 6-class Macro-F1을 산출하지 않는다**. 고정 6클래스·`zero_division=0`으로 계산한 점수는 별도 **진단 점수**로 표시할 수 있다. 진단 점수는 공식 주 지표나 완전 평가로 대체하지 않으며, 공식 Recall의 N/A와도 구분한다. 고정 클래스와 실제/예측 support, 참가자별·세션별 누락 기록을 유지한다. 빈 평가도 정답 support가 없는 상태를 0점의 완전 평가로 바꾸지 않는다.
2. **동점 판정:** 모델 순위의 점수는 반올림하지 않은 원값으로 비교하고, 절댓값 차이가 **<=1e-12**이면 동점으로 판정한다. Macro-F1 → P0 Recall → P1 Recall → P5 Recall → Accuracy → 적은 특징 수 → 기존 고정 후보 순서를 유지한다. 표시 자릿수의 반올림으로 동점을 만들지 않으며, N/A를 0으로 바꿔 순위에 사용하지 않는다.
3. **프레임 누락률의 허용 근거:** 동일 스트림의 검증된 연속 frame number **내부 간격에서만** 계산한다. 중복·리셋·출처 불확실 시 **NOT_MEASURED**와 사유를 기록한다. 구간 앞뒤에 관측하지 못한 프레임 수나 nominal FPS로 누락을 추정하지 않는다. 재생/CSV 행 인덱스를 센서 frame number로 대신하지 않으며 coverage 및 FPS와 분리한다. 이번 승인은 내부 간격이라는 범위와 NOT_MEASURED 조건을 확정한 것이며 세부 분모·출력 단위의 새 산식을 임의로 추가한 것은 아니다.
4. **개발 LOSO 필수 클래스 부족:** 개발 LOSO에서 필수 클래스가 부족하면 **모델 자동 선정을 차단**하고 fold·참가자·클래스 support와 사유를 남긴다. 불완전 fold를 건너뛰거나 클래스/참가자를 사후 삭제해 후보를 자동 선정하지 않는다. 독립 검증 자료로 부족분을 채우지 않는다.
