# AIoT 3D Viewer — 팀원 구현 인계 및 변경 범위 계약

> **문서 상태:** Engineering handoff / 연구 결과·측정 정확도 승인 문서가 아님  
> **적용 범위:** Intel RealSense D455 + MediaPipe 기반 자세 측정 결과를 받아 표시하는 3D Viewer, 외부 인체 모델 및 표시용 리깅  
> **기준:** 저장소의 승인된 Viewer 기준 커밋(인계 시 Git SHA 기입)  
> **작업 방식:** 팀원 별도 브랜치 → Pull Request → 원 개발자 검토 → 승인된 변경만 병합

## 1. 역할과 책임

- **연구·측정·분류 담당:** D455 측정, MediaPipe/Geometry, F0/F1/F2 Feature 계약, M0/M1/M2 학습·평가, Prediction V0/V1 및 연구 데이터·검증 관리. 관련 변경의 최종 승인 담당.
- **3D Viewer 담당 팀원:** 승인된 `GeometryResult` 등 측정 출력을 **읽기 전용 입력**으로 받아 인체 모델(외부 3D 에셋 포함)의 표시용 Mesh, 리깅, 관절 매핑, 정면·측면 시점, UI 및 렌더링 안정성 개선.
- **공유 경계:** 측정 알고리즘과 화면 표시 알고리즘을 분리한다. 인체형 Mesh의 자연스러움은 센서 측정 정확도 또는 자세 정상 여부의 증거가 아니다.

## 2. 수정 가능 범위

**기본적으로 허용하는 범위**

- `posture_pyvista_viewer.py` — Mesh, 시점, 카메라, 표시용 머리/목/몸통/팔 리깅, 화면 상태 및 텍스트.
- `test_posture_pyvista_viewer.py` — 기존 동작 회귀 및 신규 표시 기능 테스트.
- Viewer 전용 새 모듈·테스트·문서 — 예: 외부 에셋 로더, 관절 매핑, Viewer 전용 스냅샷/성능 테스트. 변경 파일을 PR에 모두 열거.
- `requirements-viewer.txt` — Viewer 전용 신규 패키지가 꼭 필요한 경우. 버전·설치 영향·라이선스 명시 및 승인 요청.
- 인체 모델 에셋 — 사용·재배포·논문 그림 활용 권한을 확인한 후 저장 위치와 배포 방식을 합의. 대용량 바이너리나 사용권 불명 파일을 임의로 Git에 넣지 않음.

**사전 승인 없이는 수정 금지**

- `posture_geometry.py`, `posture_geometry_probe.py`, `analyze_d455.py`, `rf_experiment.py` 및 관련 연구·측정·학습 테스트.
- `posture_3d_viewer.py` 및 그 테스트(기존 별도 Viewer 경로); 꼭 필요한 변경은 별도 요청.
- `posture_prediction.py`, 그 테스트 및 모델 추론·판정 계층.
- `RESEARCH_DATA_SCHEMA.md`, `AGENTS.md`, `CLAUDE.md`, `docs/research/**`, `docs/foundation/**`, Patch 1–8 연구 계약과 의사결정 문서.
- Canonical CSV 스키마, 라벨, 좌표계, 깊이 ROI, 필터링·결측 처리, 정규화·특징 수식, 평가 프로토콜.
- 모델 가중치, D455 연구 원본, 참가자 데이터, `eng_*.csv` 등 엔지니어링 기록 및 해시/lineage 정보.

이름이 다른 새 파일을 만들어 금지 영역의 기능을 우회 변경하는 것도 금지한다. 금지 파일 수정이 필수라면 **먼저 변경 필요성·입출력·영향·대안을 보고하고 승인받는다.**

## 3. 절대 지켜야 할 인터페이스

1. 기존 Geometry 측정 좌표와 Feature의 **단위·축·부호·의미**를 변경하지 않는다. 카메라 좌표의 기본 의미는 +X 영상 오른쪽, +Y 아래, +Z 카메라에서 멀어지는 방향이다. Viewer 렌더 좌표로의 변환은 **표시 계층 안에서 명시적으로** 수행한다.
2. 3D 인체 모델의 가상 관절·메시 표면·머리 부착점은 **시각화용 추정값**이다. D455에서 측정된 랜드마크와 별도 표시·설명할 수 있어야 한다.
3. 어깨·귀·코·엉덩이 측정값 및 Head-forward, Face Matrix의 수치 출력을 표시 편의 때문에 보정하거나 덮어쓰지 않는다. 모델의 관절 매핑에 가상의 연결점이 필요하면 내부 Viewer 전용 값으로 분리한다.
4. 임의의 smoothing, neutral offset, 개인별 calibration, 임계값, 정상/불량 판정 로직을 추가하지 않는다. 필요 시 사전 승인 요청.
5. 현재 기본 `shoulder` 시점과 기존 `--pyvista` 실행 경로를 보존한다. 선택적 `camera` 모드와 수동 잠금 동작도 의도와 다르게 변경하지 않는다.
6. 향후 분류 결과는 Viewer가 **`PredictionResult`를 읽기만 하는 방식**으로 연동한다. Viewer에서 모델 학습·로드·특징 추출을 직접 수행하지 않는다.
7. 실제 측정 데이터가 없을 때 합성 인체 움직임을 보여줄 경우 화면에 `DEMO/SYNTHETIC`임을 표시하고, 연구 관측치나 분류 성능으로 기록하지 않는다.

## 4. 현재 확인된 제한사항(팀원이 반드시 인지)

- 팔 올림/내림에 따라 어깨 랜드마크·depth 위치가 변하고 목 연결선이 달라질 수 있음. 이것이 실제 어깨 움직임인지 센서/랜드마크 영향인지는 아직 완전히 분리되지 않음.
- `shoulder` 시점은 상대적 움직임을 안정적으로 보이게 하지만 전신 공통 움직임과 입력 노이즈를 상쇄할 수 있음. **화면이 안정적이라는 것과 측정값의 정밀도는 다름.**
- `camera` 시점은 입력 좌표 변동을 더 직접 드러냄. 수동 고정 `L` 동작 및 상태 표시를 확인할 것.
- Face Matrix 검출이 없을 때 표시용 목이 숨겨질 수 있고, 얼굴 fallback 방향에는 별도 알려진 한계가 있음.
- RGB 조명·거리·가림·깊이 스파이크에 따라 실시간 표현 품질이 바뀔 수 있음.
- 기존 torso/hip 깊이와 Head-forward의 해부학적 의미·절대 정확도는 정식으로 검증된 것이 아님.
- 현재 상태는 Engineering prototype이며 Patch 8의 정식 실행이나 자세 분류 정확도 검증을 대체하지 않음.

이 항목은 기능 개선 후에도 자동으로 '해결' 처리하지 않는다. 해결을 주장하려면 변경 근거와 별도 측정 결과를 제출한다.

## 5. 외부 3D 인체 모델 인계 기준

- 모델 출처, 제작/배포자, 버전, 파일 형식(FBX/GLB 등), 원본 라이선스 URL/문서, 저장 위치, 단위(m/cm), 좌표계·회전축, 본(bone) 이름/매핑을 문서화한다.
- Adobe 도구를 통해 입수·가공했다는 사실만으로 연구용 사용·재배포·논문 그림 삽입 권한이 자동으로 보장되는 것은 아니다. 필요한 이용 범위를 직접 확인한다.
- 실측 랜드마크 ↔ 표시용 모델 관절 간 매핑표와 누락/결측 시 처리 원칙을 제출한다.
- 고개 Yaw/Pitch/Roll, 전후 이동, 팔 올림/내림, 신체 좌우 기울기에서 관절 이탈·뒤집힘·축 반전이 없는지 검증한다.
- 에셋이 없거나 로딩에 실패해도 기존 기본 Viewer 실행이 심각하게 손상되지 않도록 fallback 또는 명시적 실패 메시지를 제공한다.
- 표시용 가상 관절을 측정한 해부학적 랜드마크라고 설명하지 않는다.

## 6. PR 및 검증 계약

팀원은 **하나의 독립 기능마다 별도 커밋과 PR**을 권장한다. PR에는 아래 내용을 반드시 포함한다.

1. 기준 커밋 SHA, 작업 브랜치, 변경 파일 전체 목록.
2. 구현한 기능, 수정 이유, 측정 계층에 대한 영향 여부(`없음`이면 근거).
3. 기존 Viewer와 수정 후 View의 정면·측면 스크린샷 또는 비교 영상.
4. 실행 명령, 설치/에셋 준비 방법, 모델 파일 누락 시 동작.
5. 신규 단위 테스트 및 관련 회귀 테스트 결과; `git diff --check` 결과.
6. 가능하면 동일 Engineering 입력의 전후 렌더링 비교 및 실제 D455 Smoke 결과(조명/거리/카메라 고정 조건 명시).
7. 렌더링 시간/FPS 비교. 성능 저하가 있으면 측정 조건과 정도를 그대로 보고하고 수치 조작 금지.
8. 외부 모델 라이선스·배포 가능 여부와 미해결 위험 목록.

**허용하지 않는 작업:** 사용자 승인 없는 `main` 직접 Push, 강제 Push, 연구 스키마 변경, 측정 코드와 Viewer의 한 PR 일괄 재작성, 근거 없는 실측 정확도/정상·불량 판정 주장.

## 7. 최초 인계 절차

1. 원 개발자가 Viewer 기준 브랜치의 변경 파일을 선별 검토하고 Engineering Baseline으로 커밋·푸시한다(미검증 사항은 명시).
2. 팀원과 현재 브랜치/기준 SHA를 확인한다. 이미 개발 중인 브랜치가 있다면 커밋을 덮어쓰지 말고 diff를 검토해 안전한 병합 방식 결정.
3. 팀원은 이 문서를 읽고 작업 범위를 확인한다. AI 코딩 에이전트 사용 시에도 이 문서를 첫 프롬프트에 명시적으로 첨부/참조한다.
4. 인체 모델의 작은 기능 한 개(예: 골격 매핑·팔 동작)부터 PR을 제출해 계약 호환성과 테스트 품질을 확인한다.
5. 원 개발자 승인 후 통합한다. 최종 모델/Viewer 병합과 자세 분류 연결은 별도 승인·검증한다.
