## 이 문서 사용법

- 한 단계 = 하나의 독립 기능. **확인 → 쓸 만하다고 판단 → 커밋 → 다음 단계** 순서로 진행한다.
- 각 단계는 아래 항목을 반드시 채운다: 목표 / 상태 / 커밋 / 추가된 것 / 변경된 것 / 바뀌지 않은 것 / 기본값·호환성 / 검증 / 남은 한계.
- "변경된 것"에는 **이전 동작 → 새 동작**을 적어, 이전 단계 코드를 쓰던 사람이 무엇이 달라졌는지 바로 알 수 있게 한다.
- 새 기능은 가능하면 **기본값에서 이전 단계 동작이 그대로 유지**되도록 만든다(옵션으로 켬).
- 검증은 `단위 테스트` / `정적 검토` / `실제 D455 확인` / `미검증`을 구분해 적는다. 화면이 자연스러워 보이는 것은 측정 정확도의 증거가 아니다.
- 특정 커밋 이후 바뀐 내용 확인: `git diff <이전 단계 커밋> <이번 단계 커밋> -- mesh_avatar mesh_avatar_bridge.py run_mesh_avatar.py`

**변경된 것**
- `app.js` `camToWorld()`
  - 이전: `(x, y, z) → (x, −y, −z)` (카메라 수평 가정)
  - 이후: 카메라 X축 기준으로 `cam_pitch`만큼 되돌린 뒤 같은 축 뒤집기
    `y' = y·cosθ + z·sinθ`, `z' = −y·sinθ + z·cosθ`, 결과 `(x, −y', −z')`
  - θ = 0이면 이전과 완전히 동일.

**바뀌지 않은 것**
- 측정·연구 코드(`posture_geometry*.py`, probe, capture), 브리지가 보내는 좌표, CSV·특징·저장 데이터 — 모두 그대로. 보정은 브라우저 표시 단계에서만 적용.
- `SMOOTH`, `NEUTRAL_NOSE_DOWN_DEG` 및 기존 리깅 로직.

**기본값·호환성**
- 옵션을 주지 않으면 0° → 0단계와 같은 화면.

**검증**
- 단위/수식 확인: θ = 15°에서 기운 카메라가 본 "실제 수직"이 아바타 위쪽 `(0, 1, 0)`, "실제 수평 정면"이 `(0, 0, −1)`로 변환됨을 계산으로 확인. θ = 0에서 이전 변환과 동일.
- 회귀: `python -B -m unittest -q test_mesh_avatar_bridge` 3개 OK, `run_mesh_avatar.py` 컴파일 OK, `git diff --check` 공백 오류 없음.
- 실제 D455 확인 (엔지니어링, 1인 6초 정지 자세, 측정 기록 아님): 15° 적용 시 몸통이 뒤로 −15°로 넘어가고 머리는 여전히 숙여 보임 → 15°는 화면을 보고 고른 값이며 실측값이 아님. **고개 숙임의 주원인은 카메라 각도가 아니라 귀 depth**로 판단(0단계 문제 목록 참조).
- 설치 각도 실측 (2026-10-11, 현재 책상 설치): 휴대폰 수평계 앱, 휴대폰을 화면이 사용자 쪽을 보게 D455 윗면에 충전 단자 쪽 모서리로 세워 측정.
  y = 81.9° → 수직에서 **약 8.1°**, x = 0.6~0.7°(좌우 기울기, 무시). 방향은 "카메라가 위에서 아래로 찍는다"는 설치 상태 설명에 따라 **아래(+)**로 판단.
  한계: 모서리로 세운 손 측정이라 앞뒤로 흔들릴 수 있어 수 ° 오차 가능. 두 번째 방법(뒷면 밀착) 교차 확인은 하지 않음.
- 같은 정지 자세 데이터(1인 6초, 엔지니어링 확인)를 각도별로 재계산:

  | cam_pitch | 몸통 (hip→shoulder) | 목 (shoulder→ear) | 고개 숙임 (보정 10° 적용 후) | 고개 좌우 |
  |---|---|---|---|---|
  | 0° | −0.3° | +34.5° | +20.6° | −13.6° |
  | **8° (실측)** | −8.3° | +26.5° | +12.6° | −12.8° |
  | 15° (화면 보고 고른 값) | −15.3° | +19.5° | +5.6° | −12.2° |

  (+ = 앞으로 기울임/아래로 숙임.) 모든 각도가 보정값만큼 일관되게 회전함을 확인 → 변환 동작은 정상.
  8°에서도 고개 숙임 +12.6°, 목 +26.5°가 남음 → 귀 depth 오류(2·3단계 대상)로 판단. hip depth 신뢰가 낮아 몸통 −8.3°도 측정값으로 해석하지 않음.
- 재현 확인 (같은 날 두 번째 6초 정지 자세, 거리 약 0.75 m): 코가 귀보다 3.2 cm만 앞, 귀 간격 11.6 cm로 첫 측정(3.3 cm, 11.7 cm)과 같음 → 귀 depth 오류는 우연이 아니라 반복되는 문제.
  이때 15°에서는 고개 숙임이 +1.7°로 화면상 정면처럼 보였지만, 이는 귀 depth 오류를 과도한 보정이 가린 것이며 15°가 맞다는 근거가 아님(실측 8°에서는 +8.7°).
- 화면 육안 확인 (2026-10-11, `?cam_pitch=8`, 관절 11/11, 거리 약 0.63 m): 측면에서 몸통이 15°일 때처럼 뒤로 젖혀지지 않고 거의 수직으로 보임. 머리는 약간 숙어 보임(예상된 귀 depth 영향, 2단계 대상).
- 같은 순간 probe 패널의 Face Matrix 값: 상하 −10.79°, 좌우 +3.51°, 기울기 −0.22° (카메라 기준; 구현상 + = image-up, `HEAD_ORIENTATION_ENGINEERING_VALIDATION.md` §76).
  카메라가 8° 아래를 보면 수평으로 정면을 보는 얼굴도 카메라 기준 약 8° 아래로 나타나므로, 표시상 머리는 수평 대비 약 3° 숙임으로 해석됨.
  귀↔코 방식(같은 조건 약 +9~12° 숙임)보다 화면 기대에 가까움 → 2단계(Face Matrix) 진행 근거. 단, 한 장면 비교이며 Face Matrix의 중립값도 run마다 −5.6°~−11.6°로 변했다는 기존 기록이 있어 정확도 증거는 아님.

**완료 기준 (커밋 조건)**
1. 수평계/각도기로 D455 아래 방향 각도를 실측해 기록: `약 +8°` (완료, 위 한계 참조)

3. 위 결과를 이 섹션에 기입한 뒤 커밋.

**남은 한계**
- 귀 depth 오류로 인한 머리 방향 오류는 이 단계에서 해결되지 않음(2단계).

- 떨림: 가슴·배 두 점 사이가 약 10~20 cm로 짧아(예전 hip→어깨 약 44 cm), 각 점 depth 흔들림(표준편차 약 0.6 cm)이 각도로 2~4배 커짐 — 몸통 각도 프레임 간 변화 중앙값 1.7°, 최대 9.5°. 배 점 높이가 가려진 hip의 2D 추정을 따라 위아래로 약 1.3 cm 미끄러짐. 0.5단계에서 평활을 기본 끈 상태라 그대로 보임.
- 목: 목 기준을 어깨 → 가슴 점으로 바꾸면서 가슴 점의 떨림과 기준 자세(사람 체형 모델) 차이가 목에 그대로 들어가, 3단계(코·어깨)보다 목 움직임이 나빠짐(사용자 판단). `?smooth=0.45`로도 개선되지 않음.
- 참고(좋았던 점): 새 점의 depth 자체는 hip(표준편차 2.4~7 cm)보다 훨씬 안정적이었고, 가상 입력에서는 팔을 책상에 올려도 몸통이 숙여지지 않는 등 의도대로 동작.

**재시도 방향 (제안, 미결정)**
1. 목은 3단계 방식(코·어깨) 유지 — 이번 단계에서 목은 건드리지 않음.
2. 점 높이를 hip과 분리(예: 어깨 중점에서 어깨 너비의 몇 배 아래).
3. 두 점 사이를 넓히고, 몸통 면에 맞게 depth 영역을 넓혀 노이즈 감소.
4. 한 번에 하나씩 바꾸고 실화면 확인.
