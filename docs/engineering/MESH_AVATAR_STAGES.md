# Mesh Avatar 단계별 작업 기록

> **문서 상태:** Engineering 작업 기록 / 연구 결과·측정 정확도 승인 문서가 아님  
> **상위 규칙:** [`VIEWER_3D_HANDOFF_RULES.md`](VIEWER_3D_HANDOFF_RULES.md) — 이 문서와 충돌하면 상위 규칙이 우선  
> **작업 브랜치:** `feat/mesh-avatar`  
> **대상 코드:** `mesh_avatar/`, `mesh_avatar_bridge.py`, `run_mesh_avatar.py`, `test_mesh_avatar_bridge.py`

## 이 문서 사용법

- 한 단계 = 하나의 독립 기능. **확인 → 쓸 만하다고 판단 → 커밋 → 다음 단계** 순서로 진행한다.
- 각 단계는 아래 항목을 반드시 채운다: 목표 / 상태 / 커밋 / 추가된 것 / 변경된 것 / 바뀌지 않은 것 / 기본값·호환성 / 검증 / 남은 한계.
- "변경된 것"에는 **이전 동작 → 새 동작**을 적어, 이전 단계 코드를 쓰던 사람이 무엇이 달라졌는지 바로 알 수 있게 한다.
- 새 기능은 가능하면 **기본값에서 이전 단계 동작이 그대로 유지**되도록 만든다(옵션으로 켬).
- 검증은 `단위 테스트` / `정적 검토` / `실제 D455 확인` / `미검증`을 구분해 적는다. 화면이 자연스러워 보이는 것은 측정 정확도의 증거가 아니다.
- 특정 커밋 이후 바뀐 내용 확인: `git diff <이전 단계 커밋> <이번 단계 커밋> -- mesh_avatar mesh_avatar_bridge.py run_mesh_avatar.py`

## 승인 기록

- **2026-10-11** — 브랜치 소유자: `feat/mesh-avatar`의 Viewer 전용 코드(`mesh_avatar/`, `mesh_avatar_bridge.py`, `run_mesh_avatar.py`, 관련 테스트·문서)는 자유롭게 변경해도 됨. 병합 전에 브랜치에서 검토함.
  조건: 단계마다 이 문서에 추가·변경 내용을 정확히 기록해 사람과 AI 에이전트 모두 어디까지 진행됐고 무엇이 바뀌었는지 알 수 있게 할 것.
  이 승인은 상위 규칙 §2의 **금지 범위**(측정·연구·분류 코드, 연구 문서·스키마)에는 적용되지 않음.

## 1단계 — 카메라 설치 기울기 보정

- **목표:** D455가 아래로 기울어 설치된 만큼 표시 좌표를 되돌려, 반듯한 자세가 숙여 보이지 않게 한다.
- **상태:** 완료 · 커밋됨
- **기준 커밋:** `2ad81a8`
- **커밋:** `3a7583d` feat(mesh-avatar): stage 1 camera mounting pitch correction

**추가된 것**
- `mesh_avatar/web/app.js`
  - `camPitchDeg`, `CAM_PITCH_MAX_DEG = 60`, `parsePitch()` — URL `?cam_pitch=<도>` 읽기(+ = 카메라가 아래를 봄, ±60° 제한, 잘못된 값은 0).
  - 키보드: `[` / `]` 1°, Shift+`[` / `]` 5°, `0` 초기화. 바꾼 값은 URL에 남음. 각도를 바꾸면 평활 상태를 초기화.
  - HUD에 `카메라 기울기 보정 N°` 표시.
- `run_mesh_avatar.py` — `--cam-pitch <도>` 옵션(기본 0). 브라우저를 `?cam_pitch=` 붙여서 연다.
- `mesh_avatar/README.md` — "카메라 기울기 보정 (표시 전용)" 사용법.

**변경된 것**
- `app.js` `camToWorld()`
  - 이전: `(x, y, z) → (x, −y, −z)` (카메라 수평 가정)
  - 이후: 카메라 X축 기준으로 `cam_pitch`만큼 되돌린 뒤 같은 축 뒤집기
    `y' = y·cosθ + z·sinθ`, `z' = −y·sinθ + z·cosθ`, 결과 `(x, −y', −z')`
  - θ = 0이면 이전과 완전히 동일.

**바뀌지 않은 것**
- 측정·연구 코드(`posture_geometry*.py`, probe, capture), 브리지가 보내는 좌표, CSV·특징·저장 데이터 — 모두 그대로. 보정은 브라우저 표시 단계에서만 적용.
- `SMOOTH`, `NEUTRAL_NOSE_DOWN_DEG` 및 기존 리깅 로직.

**기본값·호환성**
- 옵션을 주지 않으면 0° → 0단계와 같은 화면.

**검증**
- 단위/수식 확인: θ = 15°에서 기운 카메라가 본 "실제 수직"이 아바타 위쪽 `(0, 1, 0)`, "실제 수평 정면"이 `(0, 0, −1)`로 변환됨을 계산으로 확인. θ = 0에서 이전 변환과 동일.
- 회귀: `python -B -m unittest -q test_mesh_avatar_bridge` 3개 OK, `run_mesh_avatar.py` 컴파일 OK, `git diff --check` 공백 오류 없음.
- 실제 D455 확인 (엔지니어링, 1인 6초 정지 자세, 측정 기록 아님): 15° 적용 시 몸통이 뒤로 −15°로 넘어가고 머리는 여전히 숙여 보임 → 15°는 화면을 보고 고른 값이며 실측값이 아님. **고개 숙임의 주원인은 카메라 각도가 아니라 귀 depth**로 판단(0단계 문제 목록 참조).
- 설치 각도 실측 (2026-10-11, 현재 책상 설치): 휴대폰 수평계 앱, 휴대폰을 화면이 사용자 쪽을 보게 D455 윗면에 충전 단자 쪽 모서리로 세워 측정.
  y = 81.9° → 수직에서 **약 8.1°**, x = 0.6~0.7°(좌우 기울기, 무시). 방향은 "카메라가 위에서 아래로 찍는다"는 설치 상태 설명에 따라 **아래(+)**로 판단.
  한계: 모서리로 세운 손 측정이라 앞뒤로 흔들릴 수 있어 수 ° 오차 가능. 두 번째 방법(뒷면 밀착) 교차 확인은 하지 않음.
- 같은 정지 자세 데이터(1인 6초, 엔지니어링 확인)를 각도별로 재계산:

  | cam_pitch | 몸통 (hip→shoulder) | 목 (shoulder→ear) | 고개 숙임 (보정 10° 적용 후) | 고개 좌우 |
  |---|---|---|---|---|
  | 0° | −0.3° | +34.5° | +20.6° | −13.6° |
  | **8° (실측)** | −8.3° | +26.5° | +12.6° | −12.8° |
  | 15° (화면 보고 고른 값) | −15.3° | +19.5° | +5.6° | −12.2° |

  (+ = 앞으로 기울임/아래로 숙임.) 모든 각도가 보정값만큼 일관되게 회전함을 확인 → 변환 동작은 정상.
  8°에서도 고개 숙임 +12.6°, 목 +26.5°가 남음 → 귀 depth 오류(2·3단계 대상)로 판단. hip depth 신뢰가 낮아 몸통 −8.3°도 측정값으로 해석하지 않음.
- 재현 확인 (같은 날 두 번째 6초 정지 자세, 거리 약 0.75 m): 코가 귀보다 3.2 cm만 앞, 귀 간격 11.6 cm로 첫 측정(3.3 cm, 11.7 cm)과 같음 → 귀 depth 오류는 우연이 아니라 반복되는 문제.
  이때 15°에서는 고개 숙임이 +1.7°로 화면상 정면처럼 보였지만, 이는 귀 depth 오류를 과도한 보정이 가린 것이며 15°가 맞다는 근거가 아님(실측 8°에서는 +8.7°).
- 화면 육안 확인 (2026-10-11, `?cam_pitch=8`, 관절 11/11, 거리 약 0.63 m): 측면에서 몸통이 15°일 때처럼 뒤로 젖혀지지 않고 거의 수직으로 보임. 머리는 약간 숙어 보임(예상된 귀 depth 영향, 2단계 대상).
- 같은 순간 probe 패널의 Face Matrix 값: 상하 −10.79°, 좌우 +3.51°, 기울기 −0.22° (카메라 기준; 구현상 + = image-up, `HEAD_ORIENTATION_ENGINEERING_VALIDATION.md` §76).
  카메라가 8° 아래를 보면 수평으로 정면을 보는 얼굴도 카메라 기준 약 8° 아래로 나타나므로, 표시상 머리는 수평 대비 약 3° 숙임으로 해석됨.
  귀↔코 방식(같은 조건 약 +9~12° 숙임)보다 화면 기대에 가까움 → 2단계(Face Matrix) 진행 근거. 단, 한 장면 비교이며 Face Matrix의 중립값도 run마다 −5.6°~−11.6°로 변했다는 기존 기록이 있어 정확도 증거는 아님.

**완료 기준 (커밋 조건)**
1. 수평계/각도기로 D455 아래 방향 각도를 실측해 기록: `약 +8°` (완료, 위 한계 참조)
2. 그 값을 넣었을 때 아바타 전체가 일관되게 회전하고 0°에서 기존과 동일함을 확인. (데이터 재계산으로 완료, 화면 육안 확인 대기)
3. 위 결과를 이 섹션에 기입한 뒤 커밋.

**남은 한계**
- 귀 depth 오류로 인한 머리 방향 오류는 이 단계에서 해결되지 않음(2단계).
- 카메라 좌우 기울기(roll)는 보정하지 않음(실측 약 0.7°라 현재 설치에서는 영향 작음).
- 설치 각도는 책상·모니터 설치마다 다르므로 코드 기본값은 0°로 두고, 실행 시 `--cam-pitch 8`처럼 지정한다.
- 손 흔들림 없는 정밀 측정이 필요하면 D455 내장 IMU(가속도계)로 읽는 방법이 있음(향후 선택 사항).

## 3단계 — 표시용 머리·목 위치 추정 개선

- **목표:** 목 방향을 귀 depth(앞으로 잘못 잡힘) 대신 **코(얼굴 정면, depth 양호) + Face Matrix**로 정해, 거북목형(머리만 앞으로)·몸 전체 앞으로·고개만 끄덕임이 **화면에서 구분되어 보이게** 함. 측정·판정이 아니라 시각화 추정.
- **상태:** 완료 · 커밋됨
- **기준 커밋:** `65f373f` (2단계)
- **커밋:** (커밋 후 기입)

**추가된 것** (`mesh_avatar/web/app.js`)
- `measureAvatarSurfaces()` / `restSurfacePoints()` / `frontMost()` — 모델 로드 시 T-pose에서 한 번: 얼굴 정중앙(|x| < 2 cm, Head~HeadTop 높이)의 가장 앞 메시 점 → `faceFrontLocal`(Head 뼈 기준), 양 어깨(Arm) 관절 중점 → `shoulderRefLocal`(Spine2 기준). **사람별 값·임의 숫자 없음**, 모델이 바뀌면 그 모델에서 다시 계산.
- `neckFromNose(measured, headAxes)` — 측정 `nose − shoulder-mid` 방향으로, 아바타 얼굴 앞면 점이 아바타 어깨 관절 중점에서 그 방향에 오도록 `Neck`을 회전(머리 Face Matrix 회전을 매번 다시 적용, 3회 반복). 측정 길이가 5~60 cm 밖이면 사용 안 함.
- `rotateBoneWorld()` 보조 함수, HUD `목: 코·어깨 / 귀 (대체) / 없음`.
- 측면 화면 전용 파란 점선 `shoulderGuide` — 아바타 어깨 관절 중점을 지나는 수직선(three.js layer 1, 정면 화면에는 안 보임). `?guide=0`으로 숨김. 그림 보조이며 측정값 아님.

**변경된 것**
- `app.js` `applyPose()` 목·머리 순서
  - 이전: 목 = shoulder-mid → ear-mid(몸통과 70% 섞음) → 그다음 머리 회전
  - 이후: 머리 회전(Face Matrix) 먼저 → 목 = `neckFromNose()`. Face Matrix·코·어깨 중 하나라도 없으면 예전 귀 방식(머리 Face Matrix는 목 이동 후 다시 적용)

- 실측 어깨 depth는 옷 표면, 아바타 기준은 관절 → 어깨 depth 개선은 4단계(측정 계층).
- 몸통은 여전히 hip 신뢰도에 의존.

## 4단계 — 측정 계층 개선 요청 (계획, 금지 범위)

- 귀 depth 샘플링, hip 가림/depth, 목·몸통 지표 정의는 `posture_geometry.py` 등 금지 범위 → Viewer에서 고치지 않고 변경 필요성·입출력·영향·대안을 정리한 요청서로 원 개발자에게 제출(상위 규칙 §2).

## 5단계 — 판정 결과 표시 연동 (계획)

- 거북목/몸통 후방 등 판정은 분류 계층의 `PredictionResult`를 읽어서 표시만 함. Viewer에서 판정·임계값 로직을 만들지 않음(상위 규칙 §3-4, §3-6).
