# E0 한 명 사전점검 로그 검토

2026-11-09. 사용자가 실행한 비정식 사전점검의 저장 숫자 로그만 읽었다. 원본 영상 열람·새 촬영·학습·모델/코드 수정·E1 최적화는 하지 않았다. 정확한 source 경로·51개 파일 hash·세부 판정·조작자 보고는 `local_private/review.json`에만 보관한다. 공식8조합·B6·IRB/정식 Patch8 보류는 유지한다.

## 결론

**모델 로드→실시간 특징→10초 집계→SVM→자원/시간 로그 저장 연결은 성공했다.** 다만 취소 동작의 실기 기록과 정상 P0 인식 안정성, 장시간15FPS 유지는 아직 확인되지 않았다. 이번 결과는 본 성능 측정이나 새로운 정확도/일반화 평가가 아니다.

실행·timing 상태는 COMPLETED, error/cleanup error는 없다.90초 상한 명령이지만 실제 stream은44.8872초다. 종료 사유가 별도 기록되지 않아 Q/창닫기 등 구체적인 종료 조작은 확정하지 않는다. 두10초 구간은 각각 입력150개/공동 유효150개, coverage100%, 적격·판정 성공이다. 판정 파이프라인 성공100%는 분류 정답률100%라는 뜻이 아니다.

## 지연과 메모리 확인

최장 처리 지연에 대응하는 같은 순서의 UI key/event wait가1162.8162ms로,1197.8839ms의 약97.07%를 차지했다. 이는 UI 이벤트 대기를 우선 점검할 근거이며 창 조작·OS scheduling 등 근본 원인을 확정한 것은 아니다. SVM 병목으로 해석하지 않는다. 참고로 Pose p95=12.0267ms, Face=6.0077ms, align=4.2346ms, UI render/submit=12.4440ms, key wait=16.8273ms다. 단계 p95를 더해 전체 p95를 만들지 않는다.

두 판정의 SVM 내부 시간은0.2047ms/0.1385ms다. Scaler 첫 호출3.3149ms, 두 번째0.2118ms로 다르지만 호출2개·예열 제외 없음이므로 안정적인 모델 추론 benchmark나 과거 warmed-up 비용과 직접 비교하는 근거로 삼지 않는다. 첫 입력부터 판정까지는 약10.03초로 고정10초 누적을 포함한다.

RSS는 시작290.82MiB, 끝360.54MiB였고 마지막10초 관측 범위는360.47~363.18MiB다. 초기 증가를 로그 메모리 누수라고 단정하거나,44.9초만으로 장시간 안정성이 입증됐다고 주장하지 않는다. 로그 상한 위반·미완료 partial 파일은 없으며, numeric duration buffer 최대256개, 자원 CPU/RAM44개·GPU43개, 구간 buffer2개다. 디스크 체크포인트는 정상 커밋됐다.

15FPS의 명목 간격은66.7ms다. p95가 이보다 작다는 사실만으로 지속15FPS를 입증하지 않는다. 이번 전체 처리량과 긴 UI 지연을 그대로 포함한 결과를 유지한다.

## 정상 자세 오분류·정지 조작

사용자는 저장된 두 구간 모두 정상 P0였고 측정 중 정지를 한 번 눌렀다고 보고했다. 출력은 P0/P1 각1개이므로 **사용자 보고 기준 정상→거북목 오분류1건**이다. 정답은 조작자 사후 보고이며 영상으로 검증하지 않았다.2개로 전체 P0 Recall/정확도나 기존120구간 성능 변화 수치를 주장하지 않는다.

취소/INCOMPLETE 구간은 저장돼 있지 않다. 현재 코드는 진행 중 hold를 취소하면 INCOMPLETE를 보존하지만, 준비 중·구간 완료 후 취소에는 active segment가 없을 수 있다. UI 명령 이벤트/당시 상태는 별도 기록하지 않아 사용자의 정지1회가 어떤 상태에서 적용됐는지 확정할 수 없다. 실제 취소 동작의 통과를 선언하지 않는다.

특징값·랜드마크·원본 영상·SVM 판정 점수를 저장하지 않았으므로 두 번째 정상 구간이 P1 쪽으로 분류된 원인을 이번 로그만으로 분해할 수 없다. 설치/자세/개인 기준 이동·모델 경계 민감성은 후속 가설이지 확인된 원인이 아니다. 특징 유효100%와 정답 인식은 구분한다.

콘솔의 `diagnostic-only: no posture classification` 문구는 기존 probe 공통 안내로 E0 실행과 맞지 않는다. 실제 로그는 SVM2회와 판정 결과를 확인한다. 이 안내 불일치와 UI 명령 이력 부재는 발견 사항으로 기록하며 이번 검토에서 코드를 변경하지 않았다. MediaPipe 경고도 있었으나 이번 저장 로그에 예외 종료나 SVM 실패는 없었다. 경고가 기하학적 품질에 영향이 전혀 없다는 결론은 아니다.

본 측정 전에는 정지 동작이 COLLECTING 중 취소로 기록되는지 확인하고, 정상 P0 오분류와 UI 긴 지연을 각각 별도 문제로 구분해 점검해야 한다. 본 실험은 이후 승인된 범위에서 같은 모델/조건으로 참가자별·여섯 자세의 반복 측정을 진행한다. 이44.9초 사전점검을 정식 E0 기준값으로 대체하지 않는다. 새 촬영·원본 변경·학습·Stage·Commit·Push는 하지 않았다.
