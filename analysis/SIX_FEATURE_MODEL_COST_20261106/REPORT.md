# 동일6특징 7개 모델 실행 비용 비교

입력: **F1,F3,F4,F6,F7,F8**. 기존 24구간/2인 LOSO의 학습12·시험12를 재사용한 비정식 오프라인 engineering benchmark다. 새 촬영·영상 열람·특징 변경·튜닝은 없다.

## 측정 조건

모델×fold×반복별 **별도 새 Python 프로세스**, 총 7×2×3=42프로세스를 순차 실행했다. 모든 모델은 seed0으로 고정했다. 이는 새 seed 탐색이나 일반화 실험이 아닌 비용 반복 측정이다. 반복/fold마다 모델 순서를 미리 정한 회전 순서로 바꿨다. 패키지 import/프로세스 시작/I/O는 시간에서 제외하며 첫 학습 호출의 초기화 비용은 포함한다.

LR/SVM/KNN은 기존 생성기·학습 fold StandardScaler를 사용했다. SVM gamma=1/9, KNN k=3 유지. RF는 500 trees/max_features2, M2 λ=0.5, 추가 scaler 없이 원래 입력을 사용했다. M1/M2 학습 시간·CPU에는 가중치 산출용 M0 학습과 순위 계산도 포함한다. 학습한 M0를 재활용하지 않고 각 방법을 독립 학습하는 총비용이다.

기존 model_benchmark.run_benchmark로 단일 구간 predict를 24회 warmup 후 120회 측정했다. 12개 시험 입력을 순환하며 모델당 6프로세스에서 operation별 720개 시간을 pool했다. classifier는 변환 완료 입력, pipeline은 scaler 또는 M1 가중치 적용+predict다. GC는 추론 측정 중만 껐고 native thread=1이다.

모델 크기는 실제 protocol5 pickle의 (classifier, scaler, M1 weights) 3-tuple bytes이며 환경·의존성·메타데이터는 제외한다. RF split weight는 모델 안에 포함된다. 각 모델의 전체 시험 예측과 저장/복원 예측이 이전 seed0 결과와 정확히 같음을 확인했다.

환경: 3.12.10, Windows-11-10.0.22631-SP0, Intel64 Family 6 Model 183 Stepping 1, GenuineIntel; logical CPU=28, NumPy=2.5.3, sklearn=1.9.1. 데스크톱 부하는 통제하지 않았다.

## 측정 범위·한계

- 학습 wall/CPU 42개, 단일 추론 시간 10,080개(7×2 operations×720)를 측정했다. 가중치 산출 의존성을 포함하면 RF forest 학습은30회, sklearn 학습은24회다.
- CPU timer는 OS 해상도/스케줄링의 영향을 받는다. 작은 차이·0ms를 비용0이나 유의한 속도 차이로 해석하지 않는다.
- 메모리 전후차는 allocator/캐시·학습 임시 메모리 잔류의 영향을 받는다. operation peak·모델 전용 메모리는 NOT_MEASURED.
- MediaPipe/Depth 특징 추출·집계·camera-to-screen 지연·실제 D455 FPS·연속 앱 안정성은 NOT_MEASURED. 아래 추론 시간으로 실제 영상 FPS나 센서 병목을 판단하지 않는다.
- 같은 개발 데이터·작은 모델의 이 PC 관측이다. 반복은 독립 참가자나 통계적 유의성을 만들지 않는다.

## 파일·검증

실행 코드는 benchmark_six_feature_models.py다. 보고서만 공개 가능한 요약이며 모델 pickle·참가자 예측·입력 hash·프로세스별 원시 시간·benchmark JSON/CSV·메모리는 local_private/에 보관한다. 기존 결과·실행 모델·공식8조합·B6·IRB HOLD·Patch8 실행 보류를 변경하지 않았다.

기존 벤치마크 합성 테스트 6개 PASS. 입력 불변, 42프로세스 완주, 동일 예측/직렬화 복원, 동일 호출수, 원시값→요약/MD 표 산술 일치를 확인했다. 전체 회귀 테스트는 실행하지 않았다.

실행: `python -X utf8 -B benchmark_six_feature_models.py`. 저장 검증만: 같은 명령에 `--verify` (학습 없음).

## 결과 해석

동일6특징의 앞선 분류 비교에서 LR·RF M0/M1·SVM-RBF·KNN의 Accuracy/Macro-F1은 모두 91.67%였고 예측도 같았다. Linear SVM은 87.50%/87.30%, M2는 RF 5 seeds 평균 89.17%/88.76%였다. 이번 비용 측정은 전 모델 seed0으로 고정했으며 그 분류 비교를 새 seed 평균으로 대체하지 않는다.

관측된 pipeline 중앙값은 LR/SVM 계열 약0.11ms, KNN 약0.17ms, RF 약0.92ms다. RF M0의 중앙값은 LR의 약8.6배이고 저장 크기도 약582KiB 대1.41KiB였다. M1/M2는 가중치 산출용 M0를 포함하므로 독립 학습 시간이 M0의 약2배였다. 실제 D455 처리량이나 영상 표시 지연이 이 배수로 달라진다는 뜻은 아니다.

같은 예측을 낸 모델 중에서는 LR·SVM-RBF가 이 작은 자료에서 빠른 추론을 보였고 LR의 저장 파일이 더 작았다. 두 모델의 미세한 시간 차이를 확정 순위로 해석하지 않는다. KNN은 여기서는 작은 파일이지만 학습 표본을 보관하는 방식이므로 다른 표본 수의 비용을 현재 결과로 보장하지 않는다.

**LR의 학습 후 Private 메모리는 약167.68MiB로 다른 모델보다 높게 관측됐다.** RSS는 약127.50MiB로 비슷했다. 따라서 작은 pickle만 보고 LR의 실행 메모리까지 더 작다고 결론내리지 않는다. 전후차 +65.99MiB에는 라이브러리 초기화·allocator·학습 중 잔류 메모리가 섞일 수 있으나 원인을 분해하지 않았다. 이 표는 학습 직후 프로세스 상태이며 배포 모델을 별도로 로드한 추론 전용 프로세스 메모리 측정이 아니다.

현재 관측만으로는 RF나 M2를 선택할 추가 분류 이득이 없었고 LR/SVM-RBF는 추론 지연·크기 측면에서 계속 검토할 근거가 있다. 최종 선택이나 실시간 적용은 별도이며 공식 조합을 변경하지 않았다. 새 생성물은 이 보고서와 벤치마크 코드, 로컬 전용 원시 기록이며 커밋·Push는 하지 않았다.

## 사용자 지정 잠정 우선 모델 — 2026-11-06

사용자의 명시적 지시에 따라 **F1·F3·F4·F6·F7·F8 + 기존 고정 LR을 잠정 최우선 개발 후보**로 지정한다. 근거는 이 반복 파일럿에서 동률인 분류 지표, 빠른 추론과 작은 저장 크기이며 LR의 Private 메모리 관측 한계는 유지한다.

이 지정은 공식8조합/선정 규칙 대체, 최종 method freeze, 실시간 배포 모델 변경, 촬영/IRB/운영 release를 뜻하지 않는다. 현재 남은 P0/P1 혼동 개선은 연구 목표로 유지하되 기존24구간의 점수를 높이는 것만으로 효과를 입증하지 않는다. 승인된 신규 개발 자료에서도 오류가 반복되는지 확인한 뒤 원인에 근거한 개선 가설을 별도로 검증한다. 이번 기록에서는 추가 특징·튜닝·모델 학습·촬영·commit/push를 수행하지 않았다.
