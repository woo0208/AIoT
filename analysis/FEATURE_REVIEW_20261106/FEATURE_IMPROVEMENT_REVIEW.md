## 1. 실제 F1~F9 정의

여기서 F1~F9는 **H9 행렬의 열 ID**다. 연구 방법군 F1/F2 또는 별도 `f1_features.py`의 `fs_x/fs_y/sh_x/sh_y/so_beta`와 다르다. 실제 순서는 [f1_sample_aggregator.py](../../f1_sample_aggregator.py)의 `H9_FEATURE_NAMES`, 수식은 [posture_geometry.py](../../posture_geometry.py)의 `compute_candidate_geometry`와 보조 함수에서 확인했다.

소문자 점은 원본 color pixel 좌표(+x 오른쪽, +y 아래), 대문자 점은 aligned D455 depth를 SDK로 deprojection한 m 단위 XYZ(+Z 카메라에서 멀어짐)다. MediaPipe 상대 z를 사용하지 않는다.

- `s=(lsh+rsh)/2`, `w=||rsh−lsh||₂`(px), `o=(leye+reye)/2`, `e=(lear+rear)/2`.
- `q=(leye+reye+lear+rear+n+c)/6`: **관측된 여섯 점 모두** 필요한 2D 머리 중심. `n`=코, `c`=턱.
- `S=(Lsh+Rsh)/2`, `H=(Lhip+Rhip)/2`, `E=(Lear+Rear)/2`, `W=||Rsh−Lsh||₂`(m), `N`=3D 코, `R`=흉부 ROI 대표점.
- Pose: 코 0, 귀 7/8, 어깨 11/12, 골반 23/24. H9 눈은 **Face iris 중심 468/473**, 턱은 Face 152이며 Pose 눈 2/5가 아니다.

F3는 `atan2(dx,dy)`의 **방향성** 각도다. 구간 대표값은 H9 9열 모두 유효한 공통 프레임에서 F3만 방향성 원형평균, 나머지는 중앙값이다. 공동 유효 ≥30프레임, 전체 공급 프레임 대비 coverage ≥50%를 유지한다. H5도 이 동일 support의 첫 5열이다. 이번 제거 분석은 이미 저장된 24×9 행렬의 열만 삭제했고 재집계·재선택하지 않았다. 따라서 B0가 F9를 입력하지 않아도 원래 H9 support는 유지된다.

`R`은 흉골 랜드마크가 아니다. 어깨 방향 단위벡터 `u`, 그 수직 중 영상 아래 방향 `v`로 중심 `s+0.35wv`, 반폭 `0.25w`, 반높이 `0.15w`인 ROI를 만든다. 영상 경계로 자른 ROI의 finite positive depth가 ≥10개일 때 중앙값×depth scale을 취하고 ROI 중심을 deprojection한다. 랜드마크 depth도 주변 pixel의 양수 유효값 중앙값을 쓴다(`half_width_px=6`, 최소 10개). 골반 대체·결측 0 대입은 없다.

### 오류의 설명 가설

기존 로컬 A/B 오류 진단의 계수 분해와 이번 특징값 대조를 재사용했다. 실제−오답 점수의 음의 특징항은 인과적 중요도가 아니다.

- **P1→P0:** F2의 머리 높이가 다른 참가자의 학습 P1 범위보다 낮고, F4·F8도 학습 P0 쪽에 가까웠다. 기존 점수 분해에서 F2/F4와 절편이 오답을 지지했다. 이번 F2 제거는 이 오류 1개를 교정했고 새 오류는 만들지 않았다. 머리–어깨 비율의 참가자 차이와 선형 경계의 전이 실패가 우선 가설이다.
- **P0→P1:** F8이 다른 참가자의 학습 P0보다 크고 학습 P1 하단에 가까웠으며 F7도 학습 P1 범위에 있었다. F9를 빼도 F8/F7의 오답 방향 기여가 남았다. 신체·코·의복/ROI·자세 수행·카메라 조건이 섞인 기준값 차이의 가능성이 있으나 원인을 분리할 수 없다.
- **P0→P2:** F5가 다른 참가자의 학습 P0 범위보다 컸고 기존 분해에서 F5/F6/F8이 P2 방향을 지지했다. F5 제거로 이 오류는 교정됐지만 다른 P1 오류가 생겼다. 얼굴/어깨 크기비의 개인차와 다중 클래스 경합을 함께 고려해야 한다.

F8의 pooled 범위가 분리돼도 실제 LOSO는 한 참가자의 12구간만으로 scaler와 **6-class 경계**를 학습한다. pooled 두 참가자 값을 보고 정한 임계값과 다르다. 따라서 범위 분리와 오분류가 동시에 존재한다. 학습 fold 표준화는 시험 참가자의 특징별 기준값 이동을 자동 제거하지 않는다. 라벨/수행 차이·개인차·설치각·depth 오차 중 어느 요인이 원인인지 이 자료로 확정하지 않는다.

기존 [B0 민감도 보고서](../lr_b0_stability_20261030_e7a914/REPORT.md)를 재사용했다. 학습 SD의 ±0.1/±0.25를 검증 열 하나에 가한 고정 모델 분석에서 F8/F7/F2는 각각 96개 조건×구간 쌍 중 예측 변경 3개로 공동 상위였고, F5/F4/F3/F6는 2개, F1은 1개였다. F2의 유리한 이동도 다른 P1→P5 오류를 동시에 만들었다. 이는 제거 분석이나 실제 D455 노이즈 검증과 다른 질문이다. 민감도 분석은 재실행하지 않았다.

### 이번 LR Leave-One-Feature-Out

기존 RF의 H5/H9 제거 실험은 모델·입력이 달라 이번 LR B0 제거를 대체할 수 없었다. 동일 LR B0 F1~F8의 완전한 제거 8조건은 발견되지 않아 아래만 실행했다. F9 제거는 실행하지 않았다.

## 4. 최종 개선 후보 2개

### 우선 1 — H3DY: F2의 metric 3D 대안

```text
Q = (Leye + Reye + Lear + Rear + N + Chin) / 6    # 각 점을 먼저 deproject
H3DY_t = (Q_y − S_y) / W
구간 H3DY = median(H3DY_t on unchanged H9 support)
```

무차원, +Y 아래로 F2와 부호를 맞춘다. 과거 설계의 C2=`(S_y−Q_y)/W`와는 부호만 반대다. 임의의 머리 중심 pixel에 평균 depth를 붙이는 계산과 다르다.

- **목표·근거:** F2가 내부 P0/P1은 분리하면서 참가자간 기준이 이동하고 제거 시 유일하게 Accuracy/Macro-F1/P1 Recall이 함께 좋아졌다. 머리와 어깨의 depth가 다를 때 2D pixel 비율에 남는 원근 영향을 실제 metric Y 차이로 줄이는 가설이다. F2 재검토의 증거는 직접적이지만 **이 새 수식의 개선 증거는 아직 없다**.
- **관측:** Pose 코0·귀7/8·어깨11/12, Face iris468/473·턱152의 aligned D455 XYZ. 골반/흉부 ROI를 사용하지 않는다.
- **기존과 차이:** F2의 투영 높이/2D 어깨너비를 3D 상대 높이/metric 어깨너비로 교체한다. F9의 전방거리 재정규화와 다른 Y축이다. F2를 동시에 추가하지 않는다.
- **가능성·비용:** 저장 engineering CSV에 8개 점 XYZ와 W가 있다. 기존 출력이 있다면 6점 평균·차분·나눗셈 O(1), 중앙값 집계 O(T) 자료 보관/처리 규모다. XYZ가 없는 실행 경로에서는 머리 6점 depth/SDK deprojection이 필요하며 2D F2보다 비용이 증가한다. 시간·FPS 증분은 NOT_MEASURED.
- **결측·단점:** 6개 head depth가 모두 필요해 2D보다 취약하다. finite XYZ·각 landmark/depth 유효 상태·유효 W가 필요하고 0 대입/보간하지 않는다. 카메라 pitch/roll, neck/head-to-shoulder 체형비, 표면 depth 오차는 남는다. 전방 이동이 높이 변화 없이 발생하면 추가 구분력이 약하다. F2의 해로운 참가자 기준차가 3D에서도 그대로 남을 수 있다.
- **기존24 계산 가능:** 과거 C2 유효성 기록상 같은 H9 지원 3,613프레임 전부 입력과 분모가 유효하다. **C2 값·분포·LR 성능은 당시에도 분석하지 않았고 이번에도 계산하지 않았다.** 24×9 집계 JSON만으로 복원할 수 없으며 engineering CSV가 필요하다.

### 우선 2 — TREAR: F8 대신 몸통축 기준 귀 전방 잔차

```text
U = H_y − S_y
V = H_z − S_z
L = sqrt(U² + V²)
TREAR_t = [U·(S_z − E_z) − V·(S_y − E_y)] / (L·W)
구간 TREAR = median(TREAR_t on unchanged H9 support)
```

무차원이며 과거 후보 **C1과 같은 정의**다. U>0인 현재 앉은 배치에서 몸통축보다 귀가 카메라 쪽이면 양수다. YZ의 어깨–골반 직선에 대한 귀 중점의 부호 있는 수직거리/W다. 기존 C1 진단을 재사용하고 새 수식으로 포장하지 않는다.

- **목표·근거:** F8에는 코 돌출·흉부 ROI·몸통 방향이 섞인다. 귀와 몸통축을 써 머리 전방 위치를 몸통 전경사와 구분할 물리적 가설이다. C3 단독 각도를 LR에 추가하는 방식과 달리 머리 위치에 몸통축 회전을 수식 안에서 적용한다. 이상적 공통 평행이동·균일 크기 변화와 YZ 내 공통 회전에 불변이다.
- **관측:** Pose 귀7/8·어깨11/12·골반23/24의 aligned D455 XYZ, E/S/H 및 W. Face/코/흉부 ROI depth는 이 후보 자체에 필요 없다.
- **EARZ 실패 반영:** `V=0, U>0`이면 `(S_z−E_z)/W=EARZ`로 환원된다. 새 가설은 **몸통 방향 보정 항**에만 있다. 수직 몸통에서는 실패한 EARZ와 같은 값이며 다시 좋아질 이유를 주장하지 않는다. C3 추가 실패도 몸통 방향이 분류 이득을 보장하지 않는 반증으로 남긴다.
- **기존 부정적 근거:** 과거 C1 진단은 P0/P1 구간 범위가 분리돼도 P1/P5 범위는 겹쳤고, F8과 전체24 r≈0.929, P0/P1/P5 12구간 r≈0.935로 높았다. 당시 C1은 보조 후보였다. C3 실패가 C1 성공을 뜻하지 않으므로 **차순위이며 F8과 동시 추가하지 않고 교체**한다. F4의 pitch 신호를 보존한다.
- **가능성·비용:** E/S/H/W가 이미 있으면 상수 개수 곱·차분·sqrt·나눗셈 O(1), 중앙값 집계 규모는 기존과 같다. 없는 경로는 양 귀·양 골반 depth/XYZ가 추가 필요하다. 시간·FPS 증분은 NOT_MEASURED.
- **결측·단점:** 귀의 배경 depth, 골반 가림·프레임 밖, 작은 L/W가 위험하다. 각 원점의 유효 flag·finite XYZ·유효 W와 L>0를 요구하고 결측 fallback은 제안하지 않는다. U≤0에서는 전방 부호 해석이 달라 현재 앉은 조건 밖으로 일반화하지 않는다. yaw/비틀기·표면 위치·목/귀 체형 차이는 남고 임상 목 각도가 아니다. F8 제거에서 P1 Recall이 떨어졌으므로 교체가 기존 유용한 코 신호를 잃을 위험도 있다.
- **기존24 계산 가능:** 과거 같은 CSV의 동일 지원 3,613프레임 전부 C1이 유효했고 24구간 중앙값이 로컬 기록에 있다. 이번에는 신규 계산·학습 없이 그 기록만 참고했다. 24×9 집계만으로 복원되지 않는다.

F4/F5 같은 머리 내부 2D 비율은 어깨 분모를 없앨 수 있지만 얼굴 형태·yaw·pitch와 작은 분모 문제가 남고 이번 자료에서 추가 근거가 없다. F7+F8은 프레임별 흉부 항을 상쇄할 수 있으나 새 관측은 아니며 선형 LR이 두 열을 이미 보유한다. F8MAD4 같은 시간 변동성은 자세 자체보다 흔들림·추적 jitter·depth 노이즈를 반영할 가능성이 있고 P0/P1의 정적 구분 근거가 약해 선정하지 않았다. 추가 조합·수식·창을 탐색하지 않았다.

### 검증·파일·공개 범위

이번에 실행한 확인은 B0 입력 hash/열·라벨·표본, 과거 seed별 OOF 동일성 및 B0 정확 재현, LOSO 학습12/시험12 분리, fold 내부 scaler와 고정 LR 설정, 수렴, 표본당 OOF 한 번, 입력 불변, 제거 지표/보고 표 산술 일치다. Python 3.12.10, NumPy 2.5.3, scikit-learn 1.9.1, native thread 1개 환경에서 수행했다. 학습 경고를 오류로 처리했으며 오류 없이 완료했다. 전체 회귀 테스트는 실행하지 않았다.

- 실행: `python -X utf8 -B review_lr_features.py`는 이번 분석만 배타 생성하며 기존 출력이 있으면 덮어쓰지 않는다. `python -X utf8 -B review_lr_features.py --verify`는 저장 수치·표·입력 불변을 검증하며 fit하지 않는다. 결과를 확인하기 위해 분석을 반복 실행할 필요는 없다.
