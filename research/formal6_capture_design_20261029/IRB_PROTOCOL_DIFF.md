# 제출 IRB 계획 대비표 — 원문 대조 전 초안

작성일: 2026-10-29. 상태: **DRAFT / IRB 원문 미확인 / 승인·변경심의 필요 여부 판단 아님**.

## 1. 확인한 자료와 확인하지 못한 자료

| 자료 | 확인 상태 | 이 문서에서의 사용 범위 |
|---|---|---|
| 제출 연구계획서 원문·제출 version/날짜 | 미확인 | 대상자 수·반복·시간·모델·보관 범위 등을 추정하지 않음 |
| 승인/보완 통지, 변경 관련 통지·조건 | 미확인 | 승인 여부·유효 범위·보완 완료를 판단하지 않음 |
| 제출 동의서·설명문 및 영상/depth/개인정보 처리 부속 문서 | 미확인 | 촬영·재검토·보관/공유 가능 범위를 확정하지 않음 |
| 별도 공통 촬영 규칙/SOP | 미확인 | 저장소 안내와 같은 문서라고 간주하지 않음 |
| 현재 저장소의 촬영 코드·Decision Log·Schema | 확인 | 현재 구현된 안내·순서·data/provenance 규칙 확인. IRB authority를 대신하지 않음 |
| 사용자 요청의 6인·6자세·5회·3+2세션·2/4 분리 | 확인 | 신규 설계안으로 구체화. 승인 증거로 쓰지 않음 |
| 기존 5종/LR 비교·오류 진단 | 확인된 파일럿 이력 | 탐색에서 LR/특징 구성을 검토했다는 배경. 정식 모델 승인/선정 아님 |

현재 작업 폴더의 문서/파일 검색과 연결 문서 세션 확인에서는 제출 IRB 원문을 찾지 못했다. 따라서 아래 표는 **실제 변경이 확정된 diff가 아니라 제출본과 대조할 잠재 변경 목록**이다. “제출본은 3회/5자세/RF만 허용했다” 같은 문장은 근거가 없어 기재하지 않는다.

## 3. R1 — 5회 반복·두 세션 확인을 별도로 남길 항목

이 항목은 R2 알고리즘과 분리해 확인한다. 분석 알고리즘이 기존 범위에 있더라도 반복/방문 부담이 같은지 별도로 확인해야 한다.

| 질문 | 확인 근거로 필요한 자료 | 현재 상태 |
|---|---|---|
| 제출본이 자세별 5회를 포함하는가? | 연구절차·반복표·대상자 설명문 원문/version | 미확인 |
| 3+2 구성이 제출 방문 수·시간·간격과 같은가? | 방문/세션 일정·중단/휴식·보상·부담 설명 | 미확인 |
| reference upright/prep/guide까지 포함한 실제 수행량이 설명됐는가? | 전체 sequence/노출 시간표 | 미확인 |
| 실패 시 추가 시도와 최대 부담이 포함됐는가? | 재촬영·탈락·중단·보완 수집 규칙 | 미확인 |
| 차이가 있을 때 어떤 검토/승인/안내 절차가 적용되는가? | 연구책임자 확인과 해당 IRB의 공식 절차/답변 | 미확인; 이 초안이 필요/불필요 판정하지 않음 |

산술 목표 180개가 유지된다고 방문 수·개인 부담이 기존과 같다고 결론 내리지 않는다. 계획 5회와 실제 유효 5회 확보를 위한 무제한 시도를 혼동하지 않는다.

## 4. R2 — 알고리즘·특징 변경 확인을 별도로 남길 항목

| 질문 | 확인 근거로 필요한 자료 | 현재 상태 |
|---|---|---|
| 제출 분석법에 LR 및 다른 분류기 비교가 포함되는가? | 통계/기계학습 분석 계획·주요 결과 정의 | 미확인 |
| H9 원본/F9 제거/H9-v2가 제출한 관측/분석 범위와 어떻게 대응하는가? | 사용 센서/관절/파생 특징·분석 절차 원문 | 미확인 |
| P5를 포함한 6-class 평가가 제출 목적/endpoint와 일치하는가? | 자세 정의·주/보조 분류 과제·라벨 정책 | 미확인 |
| 분석 변경만인지 추가 영상/관절/수집 방식·보관 변경을 동반하는가? | 변경 전후 데이터 항목·흐름·처리 주체 비교 | 미확인 |
| 학습2/검증4의 별도 사용 목적과 freeze 절차가 설명됐는가? | 데이터 분할·독립성·평가/재분석 계획 | 미확인 |
| 차이가 있을 때 필요한 확인 절차는 무엇인가? | 연구책임자·해당 IRB의 범위 판단/공식 절차 | 미확인; 자동으로 승인됨/새 승인 불필요라고 쓰지 않음 |

이 비교표는 새로운 classifier를 고르거나 알고리즘을 수정하지 않는다. 기존 2인 탐색의 LR/B 간소화 관찰은 정식 모델 승인 근거를 대신하지 않는다.

## 5. 승인/범위 확인 기록에 필요한 최소 정보

문서 이름·version·제출/결정 날짜·해당 절/쪽, 연구책임자 확인 내용, IRB의 공식 범위/조건, 확인자/확인 날짜, 남은 질의, 수정할 연구문서/동의서 여부를 추후 실제 근거와 연결한다. 현재 빈 승인표를 “승인 문서”로 발급하거나 승인번호·결정일·승인자를 추정해 채우지 않는다.

확인 상태는 `원문 미확인 / 원문 확인·일치 / 차이 확인·검토 대기 / 공식 확인 근거 확보`처럼 사실 기반으로 구분한다. “공식 확인 근거 확보”도 그 근거가 다루는 반복/촬영/분석 범위 안에서만 기술한다.

## 6. IRB 확인과 별개로 남는 연구 실행 조건

IRB 관련 범위가 확인돼도 CAP-007/009의 Patch 8 execution deferral이나 EXP-002의 Foundation/프로토콜 freeze 요구가 자동 해제되지는 않는다. 반대로 코드 감사 PASS나 설계 문서 작성도 IRB·동의 확인을 대신하지 않는다.

현재 연구 방향의 primary5와 이번 6-class 정식 설계안 사이의 연구 결정, OPEN-005의 반복·라벨/포함·metric/seed/selection 정책, 실제 장치 환경·측정품질·운영 승인도 각각 별도 근거가 필요하다. 이 문서는 그 결정을 수행하지 않는다.

## 7. 다음 원문 대조 순서

1. 제출 연구계획·설명/동의서·공통 촬영 규칙·관련 통지의 정확한 version을 확보한다.
2. 각 표 왼쪽 칸을 실제 절/쪽에 연결하고 “미확인”을 증거 있는 문구로 교체한다.
3. R1(5회/두 세션)과 R2(알고리즘/특징)를 각각 검토해 적용 절차와 범위를 확인한다.
4. 필요한 연구 문서/동의/운영 절차 확인이 끝난 뒤에만 protocol freeze와 실행 준비 여부를 별도 검토한다. 현재는 초안만 작성한 상태다.
